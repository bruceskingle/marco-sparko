# Redaction

The screenshots and examples in the documentation come from real Octopus accounts, so everything which identifies
the account holder is replaced with made up values first. The app does this itself:

- `marco-sparko --redact <profile> <new profile>` copies a profile's data to a new, offline, profile.
- `marco-sparko --redact docs`, run in the repository's directory, redacts the documents in `unredacted_docs` into
  `docs`.

Both run without opening a window, print what they did, and exit with status 1 if anything went wrong.

## The Mapping File

What replaces what is in `~/.marco-sparko-redactions.csv`, in your home directory. **Keep it private**: it pairs each
real value with the made up one which replaces it, so it reveals the real values. It must never be checked in, and is
not in the repository for that reason.

It has a pair on each line, the real value, a comma, then the made up one. A value with a comma or a double quote in
it, or which starts with `#` or a space, is in double quotes, with any double quote in it doubled. Lines starting with
`#` are comments.

```
Real Name,Made Up Name
"1, The Street",Address 1
```

The pairs at the top are your own, and always win. Redacting finds identifiers which are not in the file, makes up a
replacement for each, and adds them after the line starting `# Generated by marco-sparko --redact`. They are then
replaced the same way every time, so screenshots and documents do not change unless the data does. A generated pair can
be edited, e.g. to give a made up name a nicer value, or moved up into your own pairs. A value which is found but is
already made up, e.g. a placeholder email address, is kept as it is by adding a pair which replaces it with itself.

Each value is matched whole, ignoring case, everywhere: in file contents and in file and directory names. A value
which is all upper or lower case where it is found is replaced in the same case.

## What is Found

- **By field**, in records with named fields: IDs and numbers (`id`, `number`, `accountNumber`, `mpan`, `mprn`,
  `serialNumber`, `deviceId`, `nodeId`, `propertyId`, `userId`, `billingDocumentIdentifier`), names, addresses and
  each of their lines, apart from the country, email addresses, phone numbers, postcodes, coordinates and dates of birth.
- **By shape**, anywhere, including records stored as lists of values and file names: account numbers (`A-` and 8 hex
  digits), device IDs, UUIDs, email addresses, quoted numbers of 6 or more digits, and numbers of 6 or more digits in
  file names.
- **Secrets**, Octopus API keys and login tokens, are always replaced with a fixed placeholder, and never put in the
  mapping. The documents use the same placeholders as they always have.

A made up ID has the same shape as the real one, digits for digits and hex for hex, with prefixes such as `A-` and
separators kept, so that the app still treats it as what it is. It is random, not worked out from the real one, so it
cannot be reversed. Made up names, addresses and email addresses are placeholders, e.g. `Name12`, `Address 3` and
`person4@example.com`.

## Checks

Before anything is written, the redacted copy is checked: that no original value in the mapping is left in it, that no
secret is left in it, and that every identifier found in it is a made up one. If not, nothing is written, and the files
and the kinds of value are reported, never the values themselves. The mapping is saved before the check, so the made
up values stay the same when it is run again.

The check only knows the identifiers it can find, so look at the result before publishing it, e.g. the screenshots
themselves, or `git diff` of the documents.

## Redacted Profiles

A profile made with `--redact` has the source profile's modules and settings, but no logins: its API key is removed and
its login tokens are not copied. It is marked `offline`, so its modules count as logged in, and nothing is ever
fetched, everything comes from the copied data, see `CacheConfig::offline`. Running `--redact` again with the same
name replaces it, but a profile which is not a redacted one is never replaced.

## Documents

The documents in `unredacted_docs`, which is not in the repository, are the originals of some in `docs`, e.g. the
captured Octopus queries in `docs/octopus`. Edit the originals, not the copies in `docs`, which `--redact docs`
overwrites. The whole of each document is redacted, not only its code blocks.
